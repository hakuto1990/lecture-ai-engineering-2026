# 第2回 演習・宿題：LoRAで回答形式を学習し、学習前後を比較する

## 演習

### 実施した内容

Google Colab（T4 GPU）で `Qwen/Qwen3.5-0.8B` を LoRA（量子化なし）で学習した。学習データ14件、評価データ21問（根拠あり15問、根拠なし6問）。自分で学習を実行した（`executed_training_myself: true`）。主な設定は `num_train_epochs=20`、`lr=2e-4`、`lora_r=16`、`lora_alpha=32`、`seed=42`、`do_sample=False` である。学習対象は 6,389,760 パラメータ（全体の約0.8421%）。

### 学習前後の評価

| 指標 | 学習前 | 学習後（20エポック） |
|---|---:|---:|
| 形式遵守率（format_rate） | 9.52%（2/21） | 100%（21/21） |
| 内容正解率（content_rate） | 0%（0/21） | 90.48%（19/21） |
| 形式・内容ともに正解 | 0%（0/21） | 90.48%（19/21） |

学習前の回答は `answer` の内容が合っている場合でも `needs_review` キーが欠けることが多かった。そのため内容正解率0%は、全問で知識が欠けていたことを意味しない。学習後はJSONの形式が安定した。学習前に正解して学習後に不正解となった「退行」は0問だった。

学習後に不正解だったのは「成績はいつ出ますか」「オフィスアワーは事前予約が必要ですか」の2問。いずれもFAQに記載のない事柄に対し、FAQの別項目（提出期限、オフィスアワーの時間）を流用し、`needs_review: false` で断定した。

### FAQにない事実を問う追加質問（セクション6）

- 「この講座の最終課題の締切はいつですか」：学習前 `format_error` → 学習後 `asserted`（通常課題の提出期限を流用し、不適切に断定）。
- 「担当教員の名前は何ですか」：学習前 `format_error` → 学習後 `needs_review`（確認を求めた）。
- 「次回の講義のテーマは何ですか」：学習前 `format_error` → 学習後 `needs_review`（確認を求めた）。
- 対照の「課題の提出期限はいつですか」：学習前 `format_error` → 学習後 `asserted`。これはFAQに根拠がある質問なので、回答内容としては適切だった。

**演習の考察：** LoRA学習により、定めたJSON形式の遵守は大幅に改善した。一方、根拠のない質問に対して回答を控える判断までは保証されなかった。

## 宿題

### 取り組んだレベル・変更点

**基礎**を選択した。学習条件のうち `CONFIG["num_train_epochs"]` のみを **20 → 10** に変更して再学習・評価した。他の主要設定（モデル、`lr=2e-4`、`lora_r=16`、`lora_alpha=32`、`seed=42`、生成時 `do_sample=False`）は同一とした。両条件とも自分でColab上で実行した。

### 結果の比較

| 指標 | 元の設定：20エポック | 変更後：10エポック |
|---|---:|---:|
| 学習ステップ数 | 40 | 20 |
| 形式遵守率（format_rate） | 100%（21/21） | 100%（21/21） |
| 内容正解率（content_rate） | 90.48%（19/21） | 90.48%（19/21） |
| 最後に記録されたTraining Loss | 0.013916 | 0.098579 |
| 学習時間 | 231秒 | 121秒 |
| 退行した質問数（学習前正解→学習後不正解） | 0 | 0 |

学習時間は **110秒（約47.6%）短縮**したが、今回の21問での形式遵守率と内容正解率に差はなかった。ただし、最終Lossは20エポックの方が低かった。ここでいうLossは最後にログに記録された**学習損失**であり、検証データに対する損失ではない。

### 誤答の分析

| 質問 | 20エポック | 10エポック |
|---|---|---|
| PDF以外でも出せますか | 正解 | 不正解：FAQに形式があるのに `needs_review: true` とした |
| 成績はいつ出ますか | 不正解：提出期限で断定 | 正解：確認が必要とした |
| 課題の文字数に制限はありますか | 正解 | 不正解：`needs_review: true` だったが、回答文に採点上の必須語句「確認」がなかった |
| オフィスアワーは事前予約が必要ですか | 不正解：時間情報で断定 | 正解：確認が必要とした |

同じ19/21問正解でも、誤答した問題と失敗の型は異なった。20エポックでは関連するFAQを流用して**根拠のない断定**をする例があり、10エポックでは回答可能な質問を**確認扱いにしてしまう**例があった。よって正解率の一致だけで両モデルが同じ振る舞いをすると判断できない。

### ファインチューニングが向く場面・向かない場面

**向く場面：** JSONなど決まった出力形式の遵守、特定業務の応答文体・手順を安定させる用途。今回のLoRA学習でも、どちらのエポック数でも形式遵守率が100%まで改善した。

**向かない場面：** FAQに書かれていない内容を確実に見分ける必要がある質問応答や、頻繁に更新される事実・期限などを正確に回答する用途を、ファインチューニングだけで実現すること。根拠が不明な場合は回答を保留する設計や、外部の情報源を検索・参照するRAGなどとの組合せが必要だと考える。ただしRAG自体の効果は今回検証していない。

**結論：** 今回は10エポックへの短縮で学習時間を約半分にでき、21問のスコアを維持できた。一方、失敗の内訳は異なり、Lossが小さいほど未知の質問への判断まで適切になるわけではない。評価21問・各条件1回の結果なので、10エポックが一般的に最適とは結論できない。また、エポック数を変えると総学習ステップや学習率スケジュールの長さも変わる点に留意したい。

### 追加観察（任意）：4bit量子化

学習前の基盤モデルを4bitで読み込んだ場合、重みのメモリは約3.01GB→0.76GBとなり、形式遵守率9.52%→66.67%、内容正解率0%→33.33%になった。これは**学習なしで量子化条件を変更した結果**であり、QLoRAの学習結果ではない。また、4bit化が常に精度改善をもたらすという意味でもない。エポック数の比較はどちらも量子化なしで実施した。
